# 项目目录与 Git 历史收束

用户已批准直接删除过期开发文件、不另行备份；清理完成后把当前代码作为新的 Git 初始提交，继续使用现有 GitHub 仓库。AI 只改工作区文件并做只读 Git 查询；提交、分支、标签、Release 与远端历史由用户操作。

## 目标

- 发布准备所需的源代码、测试、夹具、锁文件、图标源文件和 CI 保持完整。
- 文件夹只保留当前工作需要的文档和脚本；一次性验收工具、已完成阶段记录和可再生成缓存直接删除。
- 安装包、签名、公证和安装升级验收留 M6-B。

## 文件范围

1. 文档：只保留本计划与执行记录。稳定架构/协作规则合并至 AGENTS.md，项目说明/构建/回归入口合并至 README.md。
2. 脚本：只留 macOS/Windows 各一个构建入口和一个回归入口。Windows 回归按已构建的单一 profile 执行；不再自动串联两种构建、脚本控制夹具或生成多份阶段报告。手动界面验收直接使用普通应用，不生成临时启动器。
3. 开发示例：删除不参与产品和测试构建的 pet_inspect CLI，并清除唯一引用。
4. 旧产物：删除空的旧 apps/macos Xcode 项目残留、.DS_Store、仓库内 Rust target、前端 node_modules/dist、旧安装包和 .scratch；锁文件、测试宠物夹具、原始品牌图及所有用户数据保留。
5. GitHub：延续已核对的历史重建方案。main 旧值 87571e2e4166da230740cc15dd5ca10e0ddd3f02；v0.1.0 旧 tag 对象 d5dcb9945980be648aa88c881096ff95881e5119；旧 Release ID 385204836。任何远端状态变化都要求停止并重新核对，不使用无条件 force/mirror。

## 完成条件

- scripts 仅四个入口；docs 仅当前计划/执行记录。
- 删除列表仅包含明确的旧开发文件和可再生成缓存；产品代码、测试夹具、依赖锁和用户数据不受影响。
- Windows 新回归入口在 Windows 宿主复跑成功；当前 Mac 会话不将 Windows 脚本的静态检查视为通过。
- GitHub Release/tag/main 与本地旧对象清理由用户按执行记录完成；未完成前不声称 Git 历史已经收束。
