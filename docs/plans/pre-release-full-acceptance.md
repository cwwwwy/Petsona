# pre-release-full-acceptance：发布前完整回归契约

## 身份与授权

- 任务ID / 版本 / 日期：`pre-release-full-acceptance` / v1.0 / 2026-10-09。
- 用户目标：在开始 M6 Windows 发布准备前，对 M0–M4 已完成内容重新做一次完整人工验收；先从前端内容界面开始。
- 用户已确认：M5 macOS 暂缓；本轮只覆盖 Windows。
- 本计划只定义验收范围、顺序、环境、证据格式和完成条件；不修改产品行为或数据格式。
- v1.1（2026-10-09，用户拍板）：外观页“UI 暴露但行为未实现”的四项开关（点击穿透、始终置顶、重力下落、活动提醒）
  在发布前从设置 UI 移除；`config.json` 字段与 runtime 命令保留兼容，行为实现与入口恢复留后续版本。
- 对应执行记录：`../execution/pre-release-full-acceptance.md`。

## 验收层次与顺序

1. **FA 前端内容界面**：设置六页、聊天窗口、主题、响应式、错误态、键盘/IME。
2. **NA 原生浮层与输入**：宠物、注视、拖动、气泡、编辑条、Composer、边界夹取。
3. **LC 生命周期与系统集成**：托盘、单实例、设置/聊天显隐、自启、退出、端口释放。
4. **PB 协议与数据兼容**：/health、/pets、/state、TTL、clear、宠物/人格/记忆文件兼容。
5. **RG 发布环境回归**：隔离目录、冷/热启动、性能、干净数据、无开发依赖运行。
6. 只有 FA–RG 全部通过或明确记录 SKIP，才进入 M6 打包与 release workflow。

## FA 前端内容界面

### FA-0 设置项旧版核对（新增前置关卡）

对照旧 macOS 收束完成态（git `6bca241` 的 `SettingsView.swift`、`settings-consolidation` v1.3），先逐项决定当前 Windows 设置是保留、恢复还是移除。FA-0 未关闭前不做 M6。

已找到用户此前对 macOS 人格/记忆的正确目标表述：`git show 6bca241:docs/execution/macos-companion-evolution.md` 开头写明：
“按 Codex 基准完成桌宠原生交互，再交付流式聊天/持久历史、可确认记忆和可导入资料塑造的人格。”
展开语义包括：

- 人格：一宠一说话方式；不保留独立人格选择器/新建/复制/删除；只保留当前宠物的语气、emoji、系统提示词；
  支持复制到其他宠物、导入、导出、重置；支持从聊天记录/人物资料生成可编辑草稿，试聊后应用；
  应用保留稳定 persona ID，试聊不写聊天历史、不写记忆，旧人格文件继续兼容。
- 记忆：记忆按宠物保存并与聊天历史分开；明确偏好自动记录，事实显示来源和更新时间，可编辑/删除/导入导出；
  待确认习惯必须人工确认；关闭记忆后停止学习和上下文注入；事件可过期、长期事实可压缩成有界画像；
  清空分级、隐私说明、删除宠物不静默删除人格/记忆。
- 设置：即时生效、无保存按钮；固定问候文案归空闲问候卡；系统页提供自启；设置项收束后不再暴露已废弃字段。
